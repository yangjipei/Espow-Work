# 尼日利亚催收自动作业｜Prototype Spec

## 1. 原型范围

- 页面模式：workspace
- 原型模式：patch_existing
- 覆盖路径：P001 案件列表 → P002 案件详情 → P003 自动作业页签 → P004 轮次详情抽屉 → P005 状态更新 Toast。
- 原则：人工案件处理保持主任务；自动作业以摘要、轨迹与详情的渐进披露方式呈现。
- 未由输入定义的布局、文案层级和示例数据均标记为 UI-DERIVED，仅用于演示交互，不新增业务规则。

## 2. 页面与模块规格

### P001 案件列表（自动任务摘要）

#### M001 顶部工作区导航
- 状态：EDITABLE
- 类型：公共导航，UI-DERIVED。
- 内容：产品标识、一级导航、当前“Collections”业务域与用户入口。

#### M002 案件工作台标题区
- 状态：EDITABLE
- 类型：页面头部，UI-DERIVED。
- 内容：标题“案件工作台”、当前日期、辅助说明、刷新按钮。
- 交互：刷新按钮模拟最近更新时间变化，不改变案件业务状态。

#### M003 筛选与搜索区
- 状态：EDITABLE
- 类型：工具栏，UI-DERIVED。
- 控件：关键词输入、自动任务状态下拉、负责人下拉。
- 交互：输入或选择后过滤 M004 的演示行；“重置”恢复全部。

#### M004 案件列表
- 状态：EDITABLE
- 内容：案件编号、客户、逾期信息、负责人、自动任务摘要、操作。
- 自动任务摘要展示：状态标签；“已完成轮次/计划轮次”；下一轮时间或异常提示。
- 交互：点击案件行或“查看案件”进入 P002；异常行以克制的风险色强调。

#### M005 列表分页
- 状态：EDITABLE
- 类型：分页，UI-DERIVED。
- 交互：用于展示列表结构，无需实现真实服务端分页。

### P002 案件详情（自动任务概览）

#### M006 案件上下文头部
- 状态：EDITABLE
- 内容：返回入口、案件编号、客户标识、案件状态、负责人。
- 交互：返回入口切回 P001。

#### M007 人工作业主区
- 状态：EDITABLE
- 类型：主内容，UI-DERIVED。
- 内容：关键案件摘要、联系方式与“发起人工联系”按钮。
- 约束：按钮保持可见、可用；进入自动作业页签后也不得用遮罩或强提醒阻断人工操作。
- 交互：“发起人工联系”仅展示轻量演示反馈，不新增真实外呼规则。

#### M008 自动任务概览卡
- 状态：EDITABLE
- 内容：整体状态、当日完成进度、最近一次结果、下一轮计划与异常摘要。
- 交互：“查看当日计划”激活 M009 的“自动作业”页签并展示 P003。

#### M009 详情页签导航
- 状态：EDITABLE
- 页签：案件概览、联系记录、自动作业。
- 交互：切换页签更新右侧内容；原型重点实现“案件概览”和“自动作业”。

### P003 当日自动作业计划与轮次轨迹

#### M010 当日任务摘要
- 状态：EDITABLE
- 内容：日期、整体状态、计划轮次数、已完成数、异常数、最后更新时间。
- 表达：数字指标紧凑排列，异常指标仅在大于 0 时用风险色。

#### M011 状态图例
- 状态：EDITABLE
- 类型：辅助图例，UI-DERIVED。
- 状态示例：待执行、执行中、已完成、异常。
- 约束：仅用于原型识别，不作为业务状态枚举定义。

#### M012 轮次轨迹
- 状态：EDITABLE
- 结构：纵向时间轴或步骤列表。
- 每轮信息：轮次名称、计划时间、状态、结果摘要、详情入口。
- 交互：点击轮次打开 P004；当前选择轮次需有高亮反馈。

#### M013 空态与异常提示
- 状态：EDITABLE
- 类型：条件反馈，UI-DERIVED。
- 规则：无计划时显示空态；存在异常时显示非阻断提示。原型默认演示“存在一条异常”的状态。

### P004 轮次执行详情（抽屉）

#### M014 抽屉头部
- 状态：EDITABLE
- 内容：轮次名称、状态、计划时间、关闭按钮。
- 交互：点击关闭按钮或遮罩关闭抽屉并返回 P003；Escape 键关闭。

#### M015 执行概览
- 状态：EDITABLE
- 内容：实际开始时间、实际结束时间、耗时、结果摘要。

#### M016 阶段轨迹
- 状态：EDITABLE
- 内容：准入、投递、回调、异常四类执行信息；使用时间、状态和摘要构成纵向记录。
- 约束：缺少某类信息时显示“暂无记录”，不推断不存在的业务过程。

#### M017 异常区
- 状态：EDITABLE
- 内容：异常阶段与说明。
- 约束：不提供未经确认的重试、豁免、审批或人工修复动作。

### P005 状态更新 Toast

#### M018 状态更新 Toast
- 状态：EDITABLE
- 类型：非阻断反馈，UI-DERIVED。
- 内容：“自动任务状态已更新”或“检测到新的异常信息”。
- 交互：短暂显示后自动消退，也可手动关闭；不得抢占焦点或阻断人工操作。

## 3. 演示交互串联

1. 原型初始显示 P001，列表中同时展示执行中、已完成、异常等示例摘要。
2. 点击首行进入 P002，人工处理区与自动任务概览同时可见。
3. 点击“自动作业”页签或“查看当日计划”，进入 P003。
4. 点击异常轮次打开 P004，展示准入、投递、回调与异常信息。
5. 关闭抽屉后留在 P003，并显示 P005 的轻量更新提示。
6. 点击“案件概览”可返回详情概览；点击“返回案件列表”回到 P001。

## 4. 视觉与响应规则

- 复用 Draft Shell 的公共结构与视觉基础，不重造公共 Shell。
- 桌面工作台优先，建议内容最大宽度 1440px；在窄屏下列表允许横向滚动，详情双栏改为单栏（UI-DERIVED）。
- 状态同时使用文字与色彩表达，不能仅依赖颜色。
- 抽屉宽度应足以阅读轨迹，但保留案件页面上下文；Toast 固定于右上区域且不覆盖主要操作。
- 所有主要交互控件提供 hover、focus 与 selected 状态。

## 5. 验收要点

- P001—P005 均可通过可见交互串联。
- HTML 中每个 M001—M018 均使用固定 MODULE 注释和 `data-module-id` 标识。
- 用户可随时返回案件列表或继续人工处理。
- 自动任务异常只作为信息提示，不生成未确认的业务动作。
- 原型为单文件可移植 HTML，无外部运行依赖。
