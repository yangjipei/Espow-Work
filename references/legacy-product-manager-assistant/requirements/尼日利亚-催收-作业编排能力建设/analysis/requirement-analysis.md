# 尼日利亚-催收-作业编排能力建设｜需求分析

## 1. Business Ask

建设面向尼日利亚催收业务的自动作业编排能力。系统每天针对每个案件生成一份当日执行计划，自动决定案件在什么时间通过点、使用什么自动工具触达，并依据前序轮次执行结果判断是否进入后续轮次，同时避免自动任务重复投递。

## 2. Actors

| 角色 / 系统 | 职责 |
|---|---|
| 决策引擎 | 判断自动编排标签；为每个案件生成当日全部轮次、执行时间、工具及后续轮次准入条件 |
| 催收系统 | 消费并执行 Decision Plan；定时筛选、路由工具、接收回调、记录执行结果与异常、提供页面提示 |
| IVR / AI Robot 服务商 | 执行自动触达并异步返回执行状态与结果 |
| 催收坐席 | 查看案件自动任务状态；继续使用现有人工能力兜底 |

## 3. Core Scenarios

### 3.1 生成当日案件计划

1. 催收系统以案件为粒度请求决策。
2. 决策引擎判断案件是否命中“自动编排标签”。
3. 未命中时返回不启用自动编排，不生成自动轮次。
4. 命中时，为该案件一次性返回当日全部轮次计划；每轮包含执行时间、工具以及进入该轮的可执行条件。

### 3.2 按轮次执行自动触达

1. 到达轮次执行时间后，催收系统读取案件最新状态与前序轮次结果。
2. 系统执行决策引擎返回的该轮准入条件。
3. 命中条件时，向本轮指定的 IVR 或 AI Robot 投递任务；未命中时跳过本轮并记录原因。
4. 同一案件、同一业务日、同一轮次不得重复投递。

### 3.3 前序轮次未完成时推进

1. 到达下一轮执行时间时，若上一轮仍未完成，将上一轮标记为失败。
2. 上一轮未完成不阻塞后续编排，系统继续执行下一轮条件判断。
3. 若服务商之后返回上一轮结果，只更新上一轮执行记录，不回滚、不取消、也不影响当前或后续轮次执行。

### 3.4 日切终止

1. 所有计划时间与日切均按尼日利亚 WAT（UTC+1）计算。
2. 日切后，案件当日尚未完成或尚未执行的自动作业直接终止，不跨日续跑。
3. 已提交服务商的任务仍可异步回调；回调仅更新对应历史轮次结果。
4. 次日由决策引擎重新生成新的案件当日计划。

### 3.5 人工兜底

1. 案件列表与详情提示案件存在自动任务，并展示当前工具、轮次、状态、结果及异常。
2. 提示不锁定案件，也不限制人工触达或其他人工作业。
3. 人工操作不取消、不暂停自动计划，不参与自动 Tool 编排。

## 4. Current Problem

- 缺少案件级、按日生成的自动触达计划，工具、时间和轮次推进无法统一编排。
- 前序结果与后续轮次之间缺少标准化衔接，容易出现提前执行、漏执行或重复触达。
- 决策与执行职责需要解耦，否则催收系统与决策引擎可能形成双份策略。
- 自动任务状态缺少面向坐席的统一提示，人工处理时无法识别当前自动作业上下文。

## 5. Desired Outcome

- 仅对命中自动编排标签的案件启用自动工具链。
- 每个案件每天只有一份权威 Decision Plan，并按计划完成最多 3 轮自动触达闭环。
- 催收系统不维护本地策略，只执行决策引擎返回的计划与条件。
- 前序轮次失败、超时或迟到回调均有明确处理口径，不阻塞既定后续轮次。
- 自动投递具备幂等控制，避免同一案件同一轮次重复推送。
- 坐席可识别自动任务状态，同时保留不受限制的人工兜底能力。

## 6. Scope

### In Scope

- 自动编排标签准入结果的消费。
- 案件级当日 Decision Plan 接收、解析与执行快照。
- 1～3 轮自动漏斗执行。
- IVR、AI Robot 两类自动工具的路由与投递。
- 按 WAT 执行定时任务与日切终止。
- 按决策引擎返回条件进行后续轮次判断。
- 自动投递幂等、执行状态、结果覆盖、异常及退出原因记录。
- 服务商迟到回调更新对应历史轮次结果。
- 案件列表与详情中的自动任务提示。
- 人工处理能力并行保留。

### Out of Scope

- 催收系统内的作业周期、策略、工具选择、轮次条件配置。
- 策略配置页、可视化编排页、轮次运营管理页和独立监控大盘。
- 催收系统自行解释自动编排标签或重算决策条件。
- 将人工处理建模为自动 Tool 或自动 Round。
- 人工触达与自动触达之间的互斥、取消或暂停机制。
- 当日计划跨日续跑。

## 7. Constraints and Rules

1. **决策唯一来源**：自动准入、轮次、工具、执行时间及进入下一轮的条件均由决策引擎给出。
2. **案件级计划**：每个案件每天生成一份计划，并一次性包含当日全部轮次。
3. **工具范围**：MVP 仅支持 IVR 与 AI Robot。
4. **轮次数量**：MVP 最多 3 轮。
5. **时间口径**：执行时间与日切统一使用 WAT（UTC+1）。
6. **按时重判**：仅在该轮执行时间到达后，使用最新案件状态和历史结果执行该轮条件。
7. **超时推进**：下一轮时间到达而上一轮未完成时，上一轮记失败，后续判断继续。
8. **迟到回调隔离**：迟到回调只更新原轮次结果，不改变已经推进的编排状态。
9. **日切终止**：日切后终止当日未执行、未完成任务；已投递任务的回调仍可入账。
10. **自动投递幂等**：建议以 `case_id + business_date + round_no` 作为业务幂等键，每次实际投递使用唯一 `dispatch_id`。
11. **人工非互斥**：自动任务仅提示，不限制人工操作，也不因人工操作改变自动计划。
12. **记录可追溯**：需保留计划解析、定时触发、条件判断、推送、服务商回调、结果更新、异常和退出原因。

## 8. Functional Requirements

| ID | 功能要求 |
|---|---|
| F01 | 接收决策引擎按案件返回的 `automation_enabled` 及当日全部轮次计划 |
| F02 | 未启用自动编排的案件不得创建自动工具任务 |
| F03 | 按 WAT 在每轮执行时间触发条件判断 |
| F04 | 执行决策引擎返回的可执行条件，并据此执行或跳过该轮 |
| F05 | 按 `tool_code` 将任务路由至 IVR 或 AI Robot |
| F06 | 防止同一案件、业务日、轮次被重复投递 |
| F07 | 接收服务商多次状态及结果回调，并更新对应轮次的最新结果 |
| F08 | 下一轮到时，自动将未完成的上一轮置为失败并继续判断 |
| F09 | 迟到回调不得影响已开始或已完成的当前及后续轮次 |
| F10 | 日切后终止当日剩余自动任务，同时允许历史轮次回调继续更新 |
| F11 | 记录每轮执行、跳过、失败、终止和异常的原因与时间 |
| F12 | 在案件列表和详情展示自动任务提示、工具、轮次、状态、结果及异常 |
| F13 | 自动任务不得限制、取消或暂停坐席人工处理 |

## 9. Acceptance Baseline

- 未命中自动编排标签的案件全天不会生成 IVR 或 AI Robot 自动任务。
- 命中标签的案件可正确解析一份包含当日全部轮次的案件级计划。
- 每轮只在其 WAT 执行时间到达后判断和投递，且相同幂等键最多成功投递一次。
- 下一轮到时，上一轮仍未完成会被记为失败，但下一轮仍按条件正常判断。
- 上一轮迟到回调可更新原轮次结果，但不会改变当前或后续轮次状态。
- WAT 日切后，当日剩余任务全部终止；已投递任务的迟到回调仍可更新历史记录。
- 人工操作在存在自动任务时仍可正常执行，且不会自动取消既定自动轮次。
- 列表和详情能够明确提示案件当前自动任务上下文。

## 10. F / A / D / Q

### Facts

- 自动编排以案件为粒度，一案一份当日计划。
- 决策引擎返回全部轮次及进入后续轮次的条件。
- 催收系统负责消费和执行，不维护本地策略。
- MVP 自动工具为 IVR 与 AI Robot，最多 3 轮。
- 人工处理仅作兜底，与自动任务并行。

### Assumptions

- “下一轮执行时间”同时作为上一轮等待结果的截止点；最后一轮的截止点为当日日切。
- Decision Plan 中的条件具有稳定、可校验且可由催收系统安全执行的表达格式；具体协议在接口设计阶段定义。

### Decisions

- WAT（UTC+1）为执行和日切的统一业务时区。
- 上一轮未完成不阻塞后续轮次，迟到回调不触发编排回滚。
- 人工触达与自动任务不做互斥控制。

### Open Questions

- 当前无阻塞需求分析的业务问题。Decision Plan 字段、条件表达式协议、服务商回调字段映射等进入后续方案设计。
