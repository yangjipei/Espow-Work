尼日利亚催收 · 作业编排业务流程

决策引擎负责“决定做什么”，催收系统负责“按计划可靠执行”。一案一天一份计划，最多三轮，超时继续推进，迟到回调不回滚，WAT 日切不跨日。

时区 WAT（UTC+1）工具 IVR / AI Robot最多 3 轮人工与自动并行

端到端流程

系统动作判断正常结果退出/异常异步回调
A生成当日计划决策引擎 → 催收系统
按案件请求决策确定 WAT 业务日
命中自动编排标签？唯一准入来源
返回 Decision Plan一次返回 1～3 轮
计划可解析？字段、时间、工具、条件
保存执行快照一案一天一份
是：准入且可解析保存计划，等待首轮执行时间。
否：未准入或不可解析未准入直接结束；解析失败记录计划异常并提示人工。
B轮次到时与准入判断催收系统
本轮时间到达使用 WAT
是否已日切？日切后不再执行
上一轮仍处理中？下一轮时间即截止点
读取最新状态案件 + 历史轮次
准入条件满足？执行计划内条件
满足进入幂等检查与工具投递。
不满足本轮标记为已跳过，记录判断依据与退出原因，等待下一轮。
若上一轮仍处理中，先将上一轮标记为“超时失败”，再继续本轮判断；不会因为上一轮无结果而阻塞。
C幂等投递与服务商执行催收系统 → IVR / AI Robot
幂等键已成功投递？case + date + round
生成 dispatch_id每次实际投递唯一
按 tool_code 路由IVR 或 AI Robot
服务商受理成功？保存调用结果
进入处理中等待异步回调
首次成功投递本轮进入处理中，保留请求、响应和时间。
重复或失败重复触发由幂等拦截；调用失败标记投递失败。两者均不阻塞后续轮次。
D异步回调与结果更新服务商 → 催收系统
服务商回调携带 dispatch_id
可定位原轮次？匹配业务日与投递记录
是否迟到回调？原轮次已超时或终止
更新原轮次状态、结果、时间、轨迹
隔离编排影响不回滚后续轮次
正常回调按字段映射更新本轮最新状态与结果。
迟到或孤立回调迟到回调仅补充原轮次；无法定位则记录异常，不修改轮次。
EWAT 日切与次日重建催收系统 → 决策引擎
到达 WAT 日切关闭当日执行窗口
终止剩余轮次未执行及未完成
继续接收历史回调只更新原轮次
次日重新请求决策不沿用昨日计划
生成次日计划进入新业务日
日切终止的是当日编排推进，不拒绝已投递任务的服务商回调。
F坐席人工并行处理催收坐席
查看自动任务提示工具、轮次、状态、结果、异常
执行现有人工处理不受自动任务锁定
自动计划照常推进双方互不暂停或取消
人工不是自动 Tool 或 Round；本阶段不设计人工与自动的互斥机制。

异常处理矩阵

场景本轮处理对后续轮次的影响
计划不可解析计划级异常，不投递当日自动流程停止
条件不满足 / 执行异常跳过或异常，记录原因后续轮次独立判断
服务商调用失败投递失败不阻塞
上一轮未完成下一轮到时置超时失败当前轮继续判断
迟到回调补充原轮次并标记迟到不回滚、不取消
日切终止当日剩余任务次日重新生成计划
