# 尼日利亚-催收-作业编排能力建设｜业务流程

## 1. 流程目标

以决策引擎生成的案件级当日 Decision Plan 为唯一策略来源，由催收系统在 WAT（UTC+1）时区内可靠执行最多 3 轮 IVR / AI Robot 自动触达，并确保轮次可推进、投递不重复、回调可追溯、当日任务不跨日。

## 2. 参与方与边界

| 参与方 | 流程职责 | 不承担的职责 |
|---|---|---|
| 决策引擎 | 判断自动编排准入；返回当日全部轮次、执行时间、工具及准入条件 | 不执行触达，不维护服务商执行状态 |
| 催收系统 | 保存计划快照；定时触发；执行条件；幂等投递；接收回调；记录状态、结果与退出原因 | 不本地配置或重算编排策略 |
| IVR / AI Robot 服务商 | 接收任务、执行自动触达、异步回调状态与结果 | 不决定后续轮次是否执行 |
| 催收坐席 | 查看自动任务上下文并按现有能力人工处理 | 不作为自动 Tool，不控制自动计划启停 |

## 3. 主流程

### 阶段 A：生成当日计划

1. 每个 WAT 业务日，催收系统按案件请求决策。
2. 决策引擎判断案件是否命中自动编排标签。
3. 未命中：返回 `automation_enabled = false`，催收系统不创建自动轮次，流程结束。
4. 命中：返回 `automation_enabled = true` 及包含 1～3 轮的当日 Decision Plan。
5. 催收系统校验计划可解析性，并以案件、业务日为粒度保存执行快照。
6. 计划不可解析：记录计划异常，不投递任何自动任务，转人工可见异常提示。

### 阶段 B：轮次到时与准入判断

对每个计划轮次依次执行：

1. 到达本轮 WAT 执行时间。
2. 检查是否已日切；已日切则终止当日剩余轮次。
3. 检查本轮是否已进入终态；已进入则不重复处理。
4. 若存在上一轮且上一轮仍为处理中，将上一轮标记为超时失败。
5. 读取案件最新状态及历史轮次结果。
6. 执行 Decision Plan 中本轮准入条件。
7. 条件不满足：本轮标记为跳过，记录条件判断结果与原因，然后等待下一轮。
8. 条件满足：进入幂等投递。

### 阶段 C：幂等投递与服务商执行

1. 以 `case_id + business_date + round_no` 检查业务幂等键。
2. 已存在成功投递记录：本次不再投递，记录重复触发并结束本轮触发动作。
3. 不存在成功投递记录：生成唯一 `dispatch_id`，按 `tool_code` 路由至 IVR 或 AI Robot。
4. 服务商受理成功：本轮进入处理中，等待异步回调。
5. 服务商受理失败或调用异常：本轮标记为投递失败；不即时重算编排，后续轮次仍按原计划到时判断。

### 阶段 D：回调与结果更新

1. 服务商携带 `dispatch_id` 回调。
2. 催收系统定位原业务日、原轮次投递记录。
3. 无法定位：记录孤立回调异常，不改变任何轮次。
4. 可以定位：按回调映射更新原轮次状态、结果及回调时间，并保留回调轨迹。
5. 若原轮次已因超时失败或日切终止，回调仅更新该轮次的最新执行结果及迟到标识，不回滚、不取消、不影响当前或后续轮次。

### 阶段 E：日切终止与次日重建

1. 到达 WAT 日切点。
2. 当日尚未执行的轮次统一终止。
3. 当日已投递但尚未完成的轮次标记为日切终止；后续回调仍可更新原轮次记录。
4. 当日 Decision Plan 不跨日续跑。
5. 次日重新请求决策并生成新的案件级计划。

### 阶段 F：坐席并行处理

1. 案件列表及详情展示自动任务是否存在、当前工具、轮次、状态、结果和异常。
2. 坐席可继续使用既有人工处理能力。
3. 人工操作不暂停、不取消、不跳过自动轮次；自动任务也不锁定人工操作。

## 4. 关键判断分支

| 判断点 | 是 | 否 |
|---|---|---|
| 命中自动编排标签？ | 生成并保存当日计划 | 不创建自动轮次，结束 |
| Decision Plan 可解析？ | 等待首轮执行时间 | 记录异常，不投递，提示人工 |
| 本轮到时已日切？ | 终止当日剩余轮次 | 继续处理本轮 |
| 上一轮仍处理中？ | 上一轮记超时失败，继续判断 | 直接继续判断 |
| 本轮准入条件满足？ | 进入幂等投递 | 本轮跳过并记录原因 |
| 幂等键已成功投递？ | 拦截重复投递 | 生成 `dispatch_id` 并投递 |
| 服务商受理成功？ | 进入处理中，等待回调 | 标记投递失败，后续轮次照常推进 |
| 回调可定位原轮次？ | 更新原轮次记录 | 记录孤立回调异常 |
| 回调属于迟到回调？ | 仅更新原轮次，不影响编排 | 正常更新本轮状态与结果 |

## 5. 轮次状态迁移

```text
待执行
├─ 条件不满足 ─────────────→ 已跳过（终态）
├─ 日切到达 ───────────────→ 已终止（终态）
└─ 条件满足、投递成功 ─────→ 处理中
   ├─ 正常结果回调 ─────────→ 已完成（终态）
   ├─ 服务商失败回调 ───────→ 执行失败（终态）
   ├─ 下一轮时间到达 ───────→ 超时失败（编排终态，可被迟到回调补充结果）
   └─ 日切到达 ─────────────→ 已终止（编排终态，可被迟到回调补充结果）

投递前调用失败 ─────────────→ 投递失败（终态）
重复定时触发 + 已成功投递 ───→ 保持原状态，仅记录幂等拦截
```

## 6. 异常与退出记录

| 场景 | 流程处理 | 后续轮次影响 |
|---|---|---|
| 计划不可解析 | 计划级异常，整份计划不执行 | 当日自动流程停止 |
| 条件执行异常 | 本轮异常并跳过投递，记录条件与错误 | 后续轮次到时继续独立判断 |
| 工具代码不支持 | 本轮投递失败 | 后续轮次不阻塞 |
| 服务商调用失败 | 本轮投递失败，保留调用记录 | 后续轮次不阻塞 |
| 上一轮长时间未完成 | 下一轮到时将上一轮置为超时失败 | 本轮继续判断 |
| 迟到回调 | 更新原轮次及迟到标识 | 不改变当前及后续轮次 |
| 孤立回调 | 记录异常并进入排查 | 不改变任何轮次 |
| 日切 | 终止未执行及未完成轮次 | 当日不再推进，次日重建 |

## 7. 流程验收要点

- 未准入案件不会产生自动轮次或服务商投递。
- 同一案件、业务日、轮次最多成功投递一次。
- 每轮仅在计划时间到达后，基于最新状态执行准入条件。
- 上一轮超时、失败或迟到回调均不阻塞既定后续轮次。
- 日切后不再执行当日剩余计划，但历史投递回调仍可入账。
- 自动任务状态对坐席可见，同时与人工处理保持非互斥。
