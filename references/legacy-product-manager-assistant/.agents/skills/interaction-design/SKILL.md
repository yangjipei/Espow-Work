# 页面与交互设计

## Purpose
把用户任务和业务流程转成信息架构、页面路径、交互状态与原型。

## When to use
根据当前产品工作场景按需使用，不因上一个 Skill 完成而自动调用。

## Interaction Contract
默认交互等级：**L3 + L2**。
遵循 Clarification / Confirmation / Decision 原则，已确认信息不重复询问。

## Output Contract
默认写入：`prototype/`（中文界面：页面原型）。
输出写入 Requirement Workspace 对应成果目录，而不是创建以 Skill 命名的用户目录。

## Style Reference Gate
- 先检查当前产品是否已有截图、原型、UI 规范。
- 有则优先继承，不重复询问风格。
- 完全没有样式上下文时，必须主动询问一次产品样式参考。
- 用户明确无参考后可自主设计，并说明设计基线。

## Non-goals
- 不自动推进下一 Skill。
- 不把模型推断静默升级为 FACT 或 DECISION。
